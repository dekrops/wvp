# Assurance map

Informative. For each thing the protocol family lets a relying party conclude, what that conclusion actually rests on today. Written on 2026-10-12 and updated the same day for the refinement theorems and the Veil experiment; each row names where to check it.

The words are used strictly:

| Word                   | Means                                                                                                                                                 |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Proved**             | A Lean theorem about a Lean definition, checked in this repository's CI, with standard axioms only. Never a proof about a program in another language |
| **Property tested**    | Not refuted on generated cases, with a fixed seed ([properties](../conformance/properties/README.md))                                                 |
| **Conformance tested** | A public implementation reproduces the published vectors, in this repository's CI ([what is checked](../conformance/ci.md))                           |
| **Differential**       | Two implementations by different authors agree on generated cases                                                                                     |
| **Assumed**            | Taken for granted by every row that depends on it. Nothing here checks it                                                                             |
| **Outside**            | Not something the protocol can establish, whatever is added to it                                                                                     |

Nothing in this table is "verified" without one of those words. A proof about the model and a test of an implementation are different rows of evidence even when they are about the same sentence of a specification.

## How the proofs themselves are checked

Five stages, each of which can fail on its own, in this repository's CI:

1. **The definitions compile**, with warnings as errors.
2. **Axioms are audited.** Every theorem is listed, and may depend only on `propext`, `Classical.choice` and `Quot.sound`. There is no `sorry`, `admit`, custom `axiom` or `native_decide`.
3. **The kernel replays the compiled declarations** (`lean4checker`): every module from its imports, and the audit module with everything it depends on into a fresh environment. This catches a declaration that reached a compiled file without the kernel accepting it. It is the same kernel, so it does not guard against a fault in the kernel.
4. **The reference evaluator reproduces the corpus**, and its command-line interface is checked.
5. **Generated cases** are reproduced by an implementation written by other people.

Stages 1 to 3 are about proofs. Stages 4 and 5 are tests. A theorem can be true and the evaluator wrong; the evaluator can pass every test and a theorem's hypothesis can still fail in the world.

## The trusted base

What a relying party relies on when it reads a result, smallest first:

- **For a proved property:** Lean's kernel; the statement of the theorem, which has to be read; and the three standard axioms.
- **For a decision:** the verifier it runs; the specification that verifier was written from; SHA-256 and Ed25519 and their implementations; its own registry and expectations.
- **For what a decision is about:** the sources. Nothing reduces this.
